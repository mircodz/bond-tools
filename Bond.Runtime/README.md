# BondTools.Runtime

Serialization for C# generated by `bond generate csharp --serialization`, compatible with Bond's Compact Binary (v1) protocol. Generated code writes and reads fields directly: no reflection and no runtime code generation, so it works with trimming and NativeAOT. It writes the bytes upstream Bond writes, and reads any payload, valid or not, as upstream Bond reads it, apart from a few [differences](#differences-from-upstream).

```csharp
byte[] bytes = order.Serialize();          // also Serialize(IBufferWriter<byte>) and Serialize(Stream)
Order copy = Order.Deserialize(bytes);     // also ReadOnlySequence<byte> and Stream
```

## Reusing instances

`Deserialize(bytes, into)` reads into an existing instance, as Bond merges: the payload's fields replace the instance's, directly typed nested structs are read into the instance's own, and container elements are appended. With `--clear`, clearing first reads it as a new instance would while retaining built-in collections and directly typed nested structs generated from the same schema file. Imported, nullable, generic, custom-mapped, and blob values may still be replaced or allocated:

```csharp
order.Clear();
Order.Deserialize(bytes, into: order);
```

## Generic structs

A generic struct takes a codec for each type parameter:

```csharp
var codec = BondCodec.Struct<Order>();
byte[] bytes = page.Serialize(codec);
Page<Order> copy = Page<Order>.Deserialize(bytes, codec);
```

`BondCodec` has a codec for every Bond type, such as `BondCodec.WString` and `BondCodec.Vector(BondCodec.Int32)`.

## `bonded<T>`

A `bonded<T>` field reads as a `BondedPayload<T>`: the struct's bytes, deserialized by `Deserialize()` and written back unchanged, including fields `T` does not know. Values such as `new Bond.Bonded<T>(value)` are written by T's codec, and other implementations of `IBonded<T>`, such as a `Bonded<Derived>`, as upstream Bond writes them.

## Custom type mappings

Values of custom-mapped types are converted by the `BondTypeAliasConverter` class in their struct's namespace, as with upstream Bond: `Convert(value, default(BondType))` before writing and `Convert(value, default(MappedType))` after reading.

## Differences from upstream

Where upstream Bond breaks the schema, BondTools.Runtime follows it:

- A base struct's type arguments keep `wstring` and `nullable`, as in `struct Item : Box<wstring>`. C# can't annotate a base type, so upstream writes and reads `string` and plain `T` there, and throws on a null element.
- `new Bond.Bonded<T>(value)` is written as the schema says. Upstream writes it as the CLR type, with the same loss in T's type arguments.
- A `bonded<T>` field must have the struct wire type. Upstream reads whatever follows as a struct.
- A missing required field is always rejected. Upstream misses it when the field just before the gap is one it skipped, such as an unknown one.

And it reads deeper payloads. Both reject a payload nested more than 64 levels deep, but upstream counts each container, nullable and bonded value as a level too, so it rejects valid payloads with as few as 33 structs nested in containers.
